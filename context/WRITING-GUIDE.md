# Writing Guide

Team writing standards for all PM artifacts. Reference this when generating customer-facing or stakeholder-facing content.

## Voice & Tone

- **Direct** — Lead with the point, not the preamble
- **Confident** — State positions clearly; hedge only when genuinely uncertain
- **Technically precise** — Use exact terms from `context/TERMINOLOGY.md`
- **Human** — Write for people, not processes

## What to Avoid

- Marketing hyperbole ("revolutionary," "game-changing," "best-in-class")
- Vague qualifiers ("various," "several," "a number of")
- Passive voice when active is clearer
- Internal jargon in customer-facing content

## Salesforce-Specific Conventions

- **Product names:** Always "Agentforce" (not "Agent Force" or "agent force")
- **Feature names:** Use exact names from `context/CAPABILITIES.md`
- **Edition references:** Include required editions (e.g., "Available in Enterprise and above")
- **Trust language:** Reference Einstein Trust Layer by name when discussing security/governance

## Format by Audience

| Audience | Structure | Tone |
|----------|-----------|------|
| **Executives** | TL;DR first, then details. Bullet points. | Business outcomes, metrics |
| **Engineering** | Specifics first, context second. Code examples. | Technical precision |
| **Customers** | Benefits before features. Getting-started steps. | Accessible, no jargon |
| **Partners** | Use cases first, technical details second. | Collaborative, enabling |
| **Internal team** | Context, decision, rationale. | Transparent, direct |

## Document-Specific Guidelines

- **PRDs:** Problem-first. Validate assumptions with data. Include acceptance criteria.
- **Status updates:** Lead with summary. Flag risks early (Yellow at first sign, not when certain).
- **Release notes:** Benefit-focused opening. Active voice. Include specific examples.
- **Strategy memos:** Start with TL;DR. Show alternatives considered. Be honest about trade-offs.
- **Launch announcements:** Lead with customer value. Include dates, steps, resources.
