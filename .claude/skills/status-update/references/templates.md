# Status Update Templates

## Executive Update

```markdown
# Status Update: [Feature Name]

**Date:** [Date] | **Release:** [4.2] | **Owner:** the PM
**Status:** Green/Yellow/Red

## TL;DR
[One sentence: current state + key message]

## Progress
**Overall:** [X]% complete | **Sprint:** [X] of [Y]

### Completed
- [Accomplishment]

### In Progress
- [Item] — [X]% complete

### Upcoming
- [Item]

## Risks & Blockers

| Issue | Severity | Impact | Mitigation | Owner |
|-------|----------|--------|------------|-------|
| [Issue] | High/Med/Low | [Impact] | [Plan] | [Name] |

## Dependencies

| Dependency | Team | Status | Impact if Delayed |
|------------|------|--------|-------------------|
| [Dep] | [Team] | Green/Yellow/Red | [Impact] |

## Asks / Decisions Needed
1. **[Ask]** — Need by [Date] — Owner: [Name]

## Next Period Plan
- [ ] [Priority item]
```

## Release Readiness

```markdown
# Release Readiness: [Feature Name]

**Release:** [4.2] | **GA Date:** [Date] | **Status:** Ready/At Risk/Not Ready

## Checklist
### Development
- [ ] Code complete / Code reviewed / Unit tests passing

### Testing
- [ ] Q3 testing / Q4 testing / Performance testing / Security review

### Documentation
- [ ] Help docs / Release notes / Admin guide

### Cross-Platform
- [ ] Cross-Team Dependency Review approved / Cross-platform alignment confirmed

### Launch
- [ ] Licensing complete / Demo ready / Enablement materials

## Open Items
| Item | Owner | Due Date | Status |
|------|-------|----------|--------|

## Go/No-Go
**Recommendation:** [Go/No-Go]
**Rationale:** [Brief explanation]
```

## ADR (Architecture Decision Record)

```markdown
# [Decision Title]

**Status:** Proposed / Accepted / Deprecated
**Date:** [Date] | **Decider:** [Name]

## Context
What situation requires a decision?

## Decision
What did we decide?

## Consequences
- Positive: [what this enables]
- Negative: [tradeoffs accepted]

## Alternatives Considered
- [Option]: [why rejected]
```
